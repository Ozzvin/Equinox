# Equinox: устройство

Для тех, кто будет менять код. Пользовательские подробности — в [details.md](details.md).

## Пакеты

| Пакет | Что делает |
|---|---|
| `cmd/equinox` | ПК-версия для Windows: окно (WebView2), трей, единственный экземпляр, регистрация в системе. |
| `cmd/equinox-server` | Серверная версия: то же ядро без окна, открывает браузер со ссылкой, где уже есть ключ. |
| `internal/app` | Поднимает всё вместе (менеджер, HTTP API, веб-интерфейс), журнал, папка данных. Общий для обеих версий. |
| `internal/core` | `Manager`: обёртка над движком anacrolix/torrent и всё, что построено сверху (очереди, лимиты, состояние, события). |
| `internal/store` | Своё файловое хранилище для движка (не mmap, см. ниже). |
| `internal/config` | Настройки (`settings.json`), значения по умолчанию, выбор папки «Загрузки». |
| `internal/api` | HTTP-обработчики `/api/*`, проверка ключа, проверка входных данных. |
| `internal/webui` | Встроенный интерфейс: один `app.js`, `index.html`, `app.css`. |
| `internal/portmap` | UPnP / NAT-PMP: проброс порта на роутере. |
| `internal/update` | Проверка и установка обновлений. |
| `internal/desktop`, `internal/buildinfo`, `internal/atomicfile` | Оконные детали Windows; версия и канал сборки; запись файлов через временный файл. |

## Как раздача проходит через ядро

```
API / файл / magnet ─► Manager.Add* ─► gate ─► движок (anacrolix) ─► store ─► файлы на диске
                                        ▲             ▲
                                        │             └─ права: syncPerm (perm.go)
                              очередь проверок       ▲
                                                    └─ очередь загрузок и очередь раздач (queue.go)
```

**Gate (gate.go).** Движок начинает хэшировать файлы, как только узнаёт info раздачи, и выключить это нельзя.
Поэтому раздача, у которой на диске уже лежат данные, сначала добавляется без info, а info отдаётся ей,
когда освобождается место в очереди проверок (`MaxConcurrentChecks`). Пока info придержана, соединений нет
(`applyConnLimit`). Раздача в пустое место идёт мимо gate: проверять нечего.

**Store (internal/store).** Штатное хранилище движка держит файлы отображёнными в память до выхода, и на Windows
их нельзя удалить или переместить. Здесь файлы открываются по требованию и закрываются, когда простаивают.
Файлы создаются разреженными (`FSCTL_SET_SPARSE`), чтобы запись в дальний конец не заливала нулями всё до неё.
Запись (загрузка) обгоняет чтение (раздачу) на том же диске (`diskpriority.go`).

**Права (perm.go).** Что раздаче можно сейчас, решает одно место, `syncPerm`: пауза пользователя, очередь
загрузок, очередь раздач и ошибка диска. Всё это сводится к двум переключателям движка (скачивать, отдавать), и
движка касаются, только когда итог поменялся. Ничто другое не должно переключать их само: они бы отменяли друг друга.

**Цикл управления (control.go, `loop`).** Раз в секунду: скорости, счётчики, проверки, gate, расписание
«черепахи», очередь загрузок, очередь раздач, лимиты по рейтингу и времени раздачи (`enforce`). Раз в 15 секунд
состояние сбрасывается на диск.

**Состояние (`stateStore` в store.go ядра).** Один JSON-файл: записи раздач (метки, порядок, пауза, счётчики).
`with` пишет на диск сразу (то, что пользователь заметит), `touch` только помечает (счётчики, которые тикают
каждую секунду), `flush` пишет по таймеру и при выходе.

## Блокировки

Порядок и правила описаны в комментарии к `Manager` ([manager.go](../internal/core/manager.go)). Коротко:
`m.mu` и `state.mu` никогда не вкладываются друг в друга; `lowMu`, `evMu`, `peerMu`, `self.mu` — листовые; порт
пробрасывается под `portCtl` → `portMu`, причём медленный `Stop()` вызывается уже без `portMu`. Новая блокировка
или новая вложенность добавляется в тот комментарий.

## Где что искать

- Очередь загрузок и очередь раздач: `queue.go` (`applyQueue`, `rankSeeds`, `applySeedQueue`).
- Лимиты по рейтингу и времени раздачи: `seedtime.go`, `control.go` (`enforce`).
- Добавление: `Add*` в `manager.go`, `stage.go` (предпросмотр пакетом), `pending.go` (ожидающие подтверждения).
- Вкладка «Пиры»: `details.go`, скорости пиров — `rates.go`; свой внешний адрес — `selfip.go`.
- Создание .torrent: `create.go`. Слежение за папкой: `watch.go`. Перемещение данных: `move.go`.
- События для уведомлений: `events.go`, `complete.go`.
